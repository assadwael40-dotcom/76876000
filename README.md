# WAEL VIEWS

مشروع أولي كامل قابل للتشغيل محليًا: واجهة عربية RTL، سيرفر Express، قاعدة بيانات SQLite دائمة، تسجيل ودخول، إنشاء طلبات، رفع إيصالات دفع خاصة، لوحة إدارة، ومراسلات بريد اختيارية عبر SMTP.

> **مهم:** هذا المشروع يدير الطلبات وإثباتات التحويل، لكنه لا يتصل تلقائيًا بمحفظة الهاتف ولا يستطيع تأكيد وصول الأموال من صورة. يجب على المدير التحقق من التحويل في تطبيق/كشف المعاملات الفعلي. كما أن هذا إصدار بداية يحتاج اختبارًا ومراجعة أمنية قبل استخدامه تجاريًا على نطاق واسع.

## المتطلبات

- Node.js 20 أو أحدث
- VS Code (اختياري)
- اتصال بالإنترنت عند تثبيت الحزم

تحقق من نسخة Node:
```bash
node -v
npm -v
```

## التشغيل على الكمبيوتر

1. فك ضغط الملف.
2. افتح مجلد `wael-views` في VS Code.
3. انسخ `.env.example` إلى ملف جديد اسمه `.env`.
4. غيّر `SESSION_SECRET` إلى قيمة عشوائية طويلة، وغيّر `ADMIN_PASSWORD` إلى كلمة مرور قوية خاصة بك.
5. افتح Terminal داخل المجلد وشغّل:

```bash
npm install
npm start
```

6. افتح `http://localhost:3000`.

سيُنشئ التطبيق قاعدة البيانات في `data/wael-views.sqlite` ومجلد الإيصالات الخاصة داخل `uploads/private` تلقائيًا.

## إنشاء حساب المدير

في ملف `.env` عيّن:
```env
ADMIN_EMAIL=assadwael40@gmail.com
ADMIN_PASSWORD=ضع_كلمة_مرور_قوية_هنا
ADMIN_NAME=WAEL VIEWS Admin
```

أعد تشغيل السيرفر. إذا لم يكن الحساب موجودًا، سيُنشأ كمدير. إذا كان الحساب موجودًا، فسيُرفع دوره إلى مدير. لا تشارك ملف `.env` مع أحد.

## رقم المحفظة

القيمة الافتراضية:
```env
WALLET_NUMBER=01099183732
```

تظهر في صفحة الدفع. تأكد من اسم المستلم في تطبيق المحفظة قبل أي تحويل. التحويل البنكي معروض كخيار إدخال إثبات، لكن بيانات الحساب البنكي لا تظهر لأنك لم تقدمها. لا تضف بيانات بنكية غير صحيحة.

## إعداد البريد الإلكتروني

لن تُرسل رسائل فعلية حتى تضبط مزود SMTP في `.env`. مثال عام:

```env
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=your-smtp-user
SMTP_PASS=your-smtp-password
MAIL_FROM=WAEL VIEWS <verified-sender@example.com>
ADMIN_NOTIFICATION_EMAIL=assadwael40@gmail.com
```

استبدل القيم بمعلومات مزود بريد فعلي، وتأكد من السماح بعنوان المرسل. سجّل الدخول بحساب المدير، ثم اضغط «اختبار البريد» في لوحة الإدارة. عند غياب إعدادات SMTP ستظل الطلبات محفوظة لكن لن تصل رسائل بريد.

## مسارات العمل

- الزائر يسجل حسابًا أو يسجل الدخول.
- المستخدم ينشئ طلب خدمة.
- صفحة طلباته تعرض رقم الطلب وحالته.
- يفتح نموذج الدفع، ويكتب رقم المحوّل، ويرفع صورة إيصال.
- يُحفظ الإيصال في مجلد خاص ولا يُقدّم عبر رابط عام.
- المدير يدخل بالحساب المهيأ ويشاهد الإيصالات من لوحة الإدارة.
- المدير يراجع المعاملة الفعلية ثم يؤكد الدفع أو يرفضه.
- تُرسل إشعارات بالبريد عند إعداد SMTP.

## بيانات الأسعار

الأسعار الافتراضية في قاعدة البيانات قيم تجريبية بالجنيه المصري، ومخزنة بوحدة القرش لتجنب مشاكل الكسور. راجع الأسعار والخدمات قبل استقبال أي عميل. يمكن للمدير تحديث سعر الخدمة أو إيقافها من API الإدارة، أو تعديل بيانات قاعدة البيانات محليًا.

## النشر

هذا المشروع يستخدم SQLite وملفات محلية، ولذلك يناسب التطوير المحلي أو خادمًا دائمًا بقرص تخزين دائم. عند النشر على منصة خادم مؤقت/Serverless، لا تعتمد على ملفات SQLite المحلية أو مجلد `uploads` كأنها تخزين دائم.

للنشر الإنتاجي، انقل قاعدة البيانات إلى PostgreSQL أو خدمة قاعدة بيانات مُدارة، وانقل الإيصالات إلى مخزن ملفات خاص يدعم صلاحيات الوصول والروابط المؤقتة. استخدم HTTPS، واضبط متغيرات البيئة في لوحة الاستضافة، واضبط `NODE_ENV=production` و`TRUST_PROXY=1` فقط إذا كان التطبيق خلف proxy موثوق. اختبر النسخ الاحتياطي والاستعادة، وراجع سياسات الخصوصية والاحتفاظ بالإيصالات، وأجرِ اختبارًا أمنيًا قبل إطلاق الموقع.

## ملاحظات أمنية

- لا ترفع `.env` إلى GitHub.
- لا تستخدم كلمة مرور المدير الافتراضية.
- لا تعرض مجلد `uploads/private` كملفات عامة.
- لا تقبل صورًا أكبر من الحد أو أنواع ملفات غير مدعومة.
- لا تعتبر صورة الإيصال دليلًا كافيًا وحدها على وصول المال.
- لا تجمع PIN أو كلمات مرور المحفظة أو رموز OTP.
- قبل الإنتاج، استخدم مخزن جلسات دائمًا، وحماية CSRF مخصصة، ونسخًا احتياطيًا، ومراقبة، واختبارات أمنية مستقلة.
